CYBERCROWD SANDBOX BUCKET CREATION DIRECTIVE V1
Cloudflare-safe operational directive for artificial sandbox bucket creation. This document prepares isolated experimentation lanes for DEV and STAGING environments.
DIRECTIVE-001
Core Rule
Sandbox buckets exist to isolate experimentation. They must never: - contaminate Production continuity - mutate Production replay - pollute live telemetry - bypass containment law - silently receive public traffic Artificial worlds stay separated from living continuity.

DIRECTIVE-003
Creation Order
Recommended order: 1. cybercrowd-dev-replay 2. cybercrowd-dev-heartbeats 3. cybercrowd-dev-sequester 4. cybercrowd-dev-deadletter freeze verify 5. cybercrowd-staging-replay 6. cybercrowd-staging-heartbeats 7. cybercrowd-staging-sequester 8. cybercrowd-staging-deadletter freeze verify
DIRECTIVE-004
Cloudflare Sandbox Discipline
All bucket creation follows: <[team build]> Meaning: 1. identify Cloudflare involvement 2. give one TASK only 3. include DO NOT boundaries 4. include ONLY action 5. include REPORT ONLY output 6. wait for Cloudflare result 7. verify before next step No broad auto-write authority.
DIRECTIVE-005
One Task Mutation Law
Only ONE bucket creation per mutation cycle. Forbidden: bulk bucket creation multi-action mutation auto-generated repair sweeps simultaneous binding mutations Reason: containment visibility verification stability replace-state awareness
DIRECTIVE-006
Isolation Guarantees
Sandbox buckets must remain: non-public non-canonical non-authoritative non-production Sandbox replay may simulate continuity. Sandbox heartbeat may simulate liveness. Sandbox systems must not become operational truth.
DIRECTIVE-007
Verification Sequence
After each bucket creation: 1. inspect bucket existence 2. inspect Production bindings 3. verify Production binding count unchanged 4. verify Pages deployment unchanged 5. verify no public exposure 6. verify no route mutation 7. freeze 8. continue Verification before expansion.
DIRECTIVE-008
Forbidden Sandbox Behavior
Forbidden: sandbox bucket auto-binding into Production Forbidden: sandbox replay merged into Production replay Forbidden: sandbox heartbeat merged into Production heartbeat Forbidden: sandbox intake routed into live lineage Forbidden: sandbox deadletter polluting live failures Forbidden: sandbox objects entering ARCHIVE
DIRECTIVE-009
Future Expansion
Future artificial environments: - DEV_CURSOR_TRANSPORT - DEV_VR_MESH - DEV_OBSERVER_SWARM - STAGING_CURSOR_TRANSPORT - STAGING_CONTINUITY_GATE - STAGING_REPLAY_RECOVERY Expansion remains compartmentalized.
DIRECTIVE-010
Final Rule
CyberCrowd experiments safely by creating isolated artificial worlds before touching living continuity. The sandbox exists so Production can survive learning.
