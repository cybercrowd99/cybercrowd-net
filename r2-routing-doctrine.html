CYBERCROWD R2 ROUTING DOCTRINE

Bucket routing, pressure separation, media propagation, and survivable storage lanes.
R2 buckets are not folders. They are operational routing chambers.

1. Doctrine Purpose

The CyberCrowd R2 Routing Doctrine defines how objects move into, through, and out of storage compartments. The purpose is not to create one giant storage blob. The purpose is to preserve lane sovereignty, replayability, lineage, and operational survivability.

Event arrives → router reads type → object routes to correct bucket → fallback catches failure → canon remains protected

graphics → cybercrowd-graphics teaser → cybercrowd-teasers album_media → cybercrowd-album raw_intake → cybercrowd-sequester approved_canon → cybercrowd-archive failed_event → cybercrowd-deadletter replay_event → cybercrowd-replay ledger_event → cybercrowd-ledger-events lineage_record → cybercrowd-lineage governance_override → cybercrowd-governance surface_cached_object → cybercrowd-surface-cache node_heartbeat → cybercrowd-node-heartbeats

5. Router Rule

The router is responsible for assigning storage destination. The object itself does not choose the bucket. The public surface does not choose the bucket. The market rail does not choose the bucket.

Router Input: event_type asset_type rail lane_source compartment_source canon_status visibility replay_state Router Output: target_bucket target_key fallback_bucket routing_receipt

6. Key Format Doctrine

Every stored object must carry a predictable key pattern so objects can be traced without guessing.

Standard Key Pattern: /lane/{lane} /rail/{rail} /event/{event_type} /date/{yyyy-mm-dd} /origin/{origin_id} /object/{object_id} /version/{version_id} Example: /lane/lane-b-processing/rail/crwd/event/crwd-transfer/date/2026-05-08/origin/origin-001/object/object-001/version/v1.json

7. Fallback Routing

If a primary bucket is unavailable or policy rejects the object, the router must not drop the event. It must route the failure into a survivable fallback path.

Primary route fails → write routing_failure event → send object reference to deadletter → preserve origin metadata → preserve replay_id → mark status = UNDER_REVIEW

8. Bucket Classifications

Hot Bucket

High access, high traffic, surface-facing, cache-aware.

Warm Bucket

Operational records, replay staging, governance review, active processing.

Cold Bucket

Archive, canon, lineage, long-term preservation, low mutation.

Quarantine Bucket

Raw, untrusted, failed, or under-review objects.

9. Existing Bucket Assignments

cybercrowd-graphics class = hot / surface asset lane = Lane C - Surface risk = traffic surge policy = cache-safe, no canon mutation cybercrowd-teasers class = hot / propagation asset lane = Lane C - Surface + Marketing Rail risk = burst traffic policy = replaceable media, preserve campaign lineage cybercrowd-album class = warm-to-cold / creator commerce asset lane = Creative Sovereignty + Archive Rail risk = settlement coupling policy = do not bind live commerce until lineage + ledger routing exist

10. Routing Receipt

Every route must create a receipt so the system knows what moved, where it moved, and why.

{ "routing_receipt_id": "route_0001", "event_id": "evt_0001", "origin_id": "origin_0001", "replay_id": "replay_0001", "source_lane": "Lane A - Intake", "source_compartment": "Truth Compartment", "target_bucket": "cybercrowd-sequester", "target_key": "/lane/lane-a-intake/rail/archive/event/raw-intake/date/2026-05-08/origin/origin-0001/object/object-0001/version/v1.json", "fallback_bucket": "cybercrowd-deadletter", "status": "ROUTED", "timestamp": "2026-05-08T00:00:00.000Z" }

11. Must Never Happen

  • No bucket becomes a universal storage blob.
  • No public surface writes directly to canon.
  • No album commerce object goes live without lineage.
  • No failed object disappears without deadletter record.
  • No governance override bypasses routing receipt.
  • No CRWD settlement record is stored without event lineage.
  • No bucket policy silently changes without governance event.

12. Final R2 Routing Lock

R2 routing exists to preserve operational survivability. A bucket is not merely where a file lives. A bucket is where pressure is contained, classified, traced, replayed, or canonized.

R2 Bucket = operational pressure chamber Router = traffic controller for event physics small target fails whole environment survives
