CYBERCROWD DUAL DEPLOYMENT AUDIT

Read-only deployment truth record and lane protection page.
Do not panic-patch. Do not flatten. Do not condense. Document the real topology first.

1. Audit Finding

CyberCrowd is currently operating through a dual deployment model. The live surface is delivered through the Pages pipeline, while runtime capability remains connected through an independently deployed Worker service binding.

Pages Surface Lane + MAIN_WORKER Runtime Lane

This is not a total failure condition. It is an active topology that must be understood before any cleanup or migration occurs.

2. Pages Surface Lane

The Pages pipeline is succeeding and remains the public visible layer.

  • Build command is effectively no-op.
  • Pages deploys the visible surface.
  • Live site is not blocked by the red Workers Build indicator.
  • Pages should not be flattened into a single-page coffin.
Pages Surface Lane = public visible layer

3. Worker Runtime Lane

The project has a service binding connected to an independently deployed Worker.

MAIN_WORKER → cybercrowd-net

This means the runtime lane exists and should not be deleted blindly. It must be separated, mapped, or intentionally migrated only when the architecture is ready.

4. Red Workers Build Check

The red Workers Build indicator is currently understood as a detection artifact caused by Worker configuration being visible in the repository.

  • Worker Builds are not confirmed as blocking the live Pages deployment.
  • The red check does not mean the whole environment failed.
  • The live Pages deployment continues to operate.
  • The indicator should be treated as topology noise until the lane is intentionally cleaned.
Red Workers Build check = detection artifact not live-site collapse

5. R2 Binding Status

The ALBUM binding was intentionally parked after Cloudflare R2 validation returned a timeout during deploy.

  • ALBUM is unbound / parked.
  • GRAPHICS remains preserved.
  • TEASERS remains preserved.
  • The bucket itself was not deleted.
ALBUM → parked GRAPHICS → preserved TEASERS → preserved

6. Current Doctrine Lock

  • No condensing.
  • No rollback.
  • No flattening.
  • No single-page coffin.
  • No killing Workers or R2 future lanes.
Pages Surface Lane = public visible layer Worker Lane = separated runtime R2 Lane = separated storage and media

7. Correct Next Action

Do not clean or migrate blindly. The correct next step is documentation and lane mapping.

Any future cleanup must preserve the operational principle:

small target fails whole environment survives

CyberCrowd should remain an operational environment with survivable lanes.

8. Final Audit Statement

CyberCrowd is not broken because one deployment indicator is red. The visible site, Worker lane, R2 future lane, operations surfaces, continuity doctrine, and survivable lane model must be treated as separate operational compartments.

A red indicator must not cause destructive simplification.
