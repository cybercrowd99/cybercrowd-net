CYBERCROWD NODE REGISTRATION DEVICE FINGERPRINT LAW V1
Node registration and device fingerprint doctrine for CyberCrowd. This document defines how devices become known to the system without automatically becoming trusted authority.
FINGERPRINT-001
Core Rule
Device identity is not device authority. Registration means: the device is known. Fingerprinting means: the device can be recognized again. Trust means: the device has earned scoped participation. Authority means: the device is permitted to perform a governed action. These are separate states.

FINGERPRINT-003
Fingerprint Sources
Device fingerprint may include privacy-safe derived signals: - device class - browser/runtime family - screen class - operating system family - local app install identity - generated device key - node registration secret - public key fingerprint Fingerprint must not depend on invasive tracking. CyberCrowd should prefer: generated keys + user-approved registration + public key fingerprints over hidden surveillance.
FINGERPRINT-004
Factory-Reset Device Onboarding
A factory-reset old phone may enter as: device_class: sandbox node or observer node initial trust: Level 0 or Level 1 allowed actions: registration public viewing sandbox heartbeat sandbox replay simulation forbidden actions: canon writes governance authority lineage mutation archive mutation unrestricted transport
FINGERPRINT-005
Old Hardware Reuse Rule
Old phones and laptops may become useful infrastructure when: - factory reset - registered as a node - assigned a device class - scoped to sandbox or observer lanes - heartbeat tested - replay tested - trust escalated slowly Discarded hardware becomes operational resource, not automatic authority.
FINGERPRINT-006
Registration Flow
1. device opens registration surface 2. user assigns device label 3. device class selected 4. generated device key created 5. fingerprint hash created 6. node_id assigned 7. initial trust level assigned 8. heartbeat scope assigned 9. replay scope assigned 10. registration event recorded 11. device enters probation
FINGERPRINT-007
Trust Linkage
Registration links to trust ladder. A registered device begins at: Level 0 or Level 1 Escalation requires: - heartbeat stability - replay consistency - no quarantine triggers - reviewed participation history Registration alone never grants high trust.
FINGERPRINT-008
Replay Linkage
Every registered device may receive a replay scope. Replay scope defines: - whether the device can emit replay events - whether the device can read replay events - whether the device can participate in reconstruction - whether the device is sandbox-only Replay identity must remain tied to node_id.
FINGERPRINT-009
Heartbeat Linkage
Heartbeat scope defines where liveness is recorded. Sandbox devices: DEV_HEARTBEATS or STAGING_HEARTBEATS Production devices: NODE_HEARTBEATS A device must not emit heartbeat traffic into a higher authority lane than its trust scope allows.
FINGERPRINT-010
Re-Registration Rules
Re-registration is required when: - device is factory reset - device key changes - ownership changes - device class changes - suspicious behavior occurred - trust level was revoked - fingerprint mismatch occurs Re-registration does not restore previous trust automatically.
FINGERPRINT-011
Quarantine Triggers
Route device to SEQUESTER when: - fingerprint mismatch occurs - heartbeat pattern changes unexpectedly - replay ID conflicts - device claims higher authority than assigned - device attempts forbidden route - device appears duplicated - device emits suspicious transport behavior Quarantine requires review before reactivation.
FINGERPRINT-012
Privacy Boundary
CyberCrowd device fingerprinting must remain bounded. Allowed: - user-approved registration - generated node keys - public key fingerprints - device class metadata - replay and heartbeat records Forbidden: - covert personal tracking - unnecessary surveillance - invisible cross-site tracking - collecting unrelated private data - authority escalation through hidden profiling The system recognizes devices for continuity, not exploitation.
FINGERPRINT-013
Final Rule
CyberCrowd may recognize a device, but must not blindly trust it. Registration creates identity. Heartbeat proves presence. Replay proves continuity. Governance approves escalation.
