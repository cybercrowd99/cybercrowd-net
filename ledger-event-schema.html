Canonical event structure for lineage, replayability, governance, propagation, and survivability.
Every ledger event must be traceable, replayable, and canon-safe.

1. Schema Purpose

The CyberCrowd Ledger Event Schema defines the exact structure every ledger entry must follow. It prevents hidden debt, silent overrides, duplicate counting, broken lineage, and uncontrolled mutation.

The ledger event is the smallest survivable unit of operational memory.

Ledger Event = what happened where it happened who caused it what rail it affected what value moved what lineage it belongs to whether it can replay whether governance touched it

4. Event Status Values

PENDING

Event received but not fully committed.

COMMITTED

Event accepted into canonical operational memory.

REVERSED

Event counteracted by a later reversal event, not deleted.

ARCHIVED

Event finalized into canonical archive lineage.

FAILED

Event failed and must route to dead-letter or review.

UNDER_REVIEW

Event frozen by governance or anomaly detection.

7. Replay Rule

Every event must include a replay ID. The replay ID prevents duplicate counting and allows deterministic reconstruction.

Replay Rule: same replay_id + same event_type + same origin_id = same event If replay is attempted: - do not duplicate value - compare payload hash - return existing canonical event - log replay attempt if mismatch

8. Governance Override Rule

Governance may annotate, freeze, reverse, or update future rule sets. Governance may not silently delete or rewrite past canon.

Governance Event Requirements: governance_id admin_id authority_role old_value new_value reason effective_start_time timestamp signature_reference Rule: governance event must be committed before its effect applies

9. Native Unit and USD Mirror Rule

Every event keeps the native unit and a USD mirror at event time. The USD mirror is for audit/reference only. It is not a redemption promise.

native_amount = value in original rail native_unit = CRWD | USD | ACCESS | CREDIT | NODE | STORAGE usd_mirror_amount = native_amount × usd_mirror_rate_at_event_time Mirror Rule: future price changes do not mutate past events

10. Canon Safety Rules

  • No event is deleted after commit.
  • Corrections are new events.
  • Reversals are new events.
  • Overrides are new governance events.
  • Past payout math is not silently rewritten.
  • Surface lanes cannot mutate canon.
  • Market movement cannot rewrite historical mirrors.
Append-only rule: state = reduce(all_events_in_order) Canon is derived. Canon is not hand-edited.

11. Ledger Event Validation

An event is valid only if: event_id exists event_type is allowed event_status is allowed timestamp exists rail exists lane_source exists compartment_source exists replay_id exists native_unit exists usd_mirror_rate exists canonical_record_id exists If event affects payout: split_rule_id required If event affects governance: governance_id required If event reverses another event: previous_event_id required
