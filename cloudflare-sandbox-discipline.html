CYBERCROWD CLOUDFLARE SANDBOX DISCIPLINE
Operational discipline for using Cloudflare AI safely during CyberCrowd infrastructure work. This doctrine exists because Cloudflare mutation tools can replace state instead of merging state.
DISCIPLINE-001
The Six-Step Safe Cycle
1. inspect only 2. report only 3. define error only 4. review 5. apply one correction only 6. verify only No combined research + repair + save prompts. No multi-action repair chains. No open-ended optimization requests.
DISCIPLINE-002
Prompt Structure
Every Cloudflare mutation prompt must use: TASK: one exact directive only DO NOT: containment boundaries ONLY: allowed action lane REPORT ONLY: verification output The word TASK must anchor one directive at a time.
DISCIPLINE-003
Binding Rule
Always restate the full active binding set during any binding mutation. Never assume merge-state behavior. Reason: Cloudflare may treat a patch as a replacement state. If existing bindings are omitted, they may disappear.
DISCIPLINE-004
Failure Mode
Failure Mode: timeout → loses directive containment → enters fast-fix mode → strips configuration → plugs one path → returns partial success This is not acceptable for CyberCrowd infrastructure.
DISCIPLINE-005
Safe Mode
Safe Mode: small scoped tasks + containment boundaries + verification cycles + state freezing One lane. One correction. One verification.
DISCIPLINE-006
Replace-State Warning
Cloudflare operations must be treated as replace-state unless proven otherwise. Do not say: add this one thing Say: preserve these existing things and add this one thing Then verify full state.
DISCIPLINE-007
CyberCrowd Rule
Controlled expansion beats fast repair. Infrastructure must not be trusted because it succeeded once. It must be verified after every mutation. Build empty boxes first. Verify connections second. Live transport last.
