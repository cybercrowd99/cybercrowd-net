CYBERCROWD DEV STAGING EXPERIMENT LANES V1
Safe experimentation doctrine for CyberCrowd. This document separates sandbox work, staged proof work, and protected production continuity.
LANE-001
Core Protection Wall
Safe experimentation wall: no live R2 contamination no production binding mutation no public transport testing no creator upload testing in production Experiments belong in DEV. Proof belongs in STAGING. Continuity belongs in PRODUCTION.
LANE-002
Environment Roles
Environment Purpose Allowed Behavior Forbidden Behavior
DEV break things safely mock events, fake buckets, simulated transport, draft files live Production R2 writes
STAGING prove before release test routes, controlled replay, preview bindings, fake intake public creator traffic
PRODUCTION protected live surface verified releases only experiments
LANE-003
DEV Rules
DEV may use: - fake events - mock replay chains - local test payloads - simulated Magic Cursor events - fake heartbeat pulses - fake uploads - draft route experiments DEV must not: - write to Production R2 - mutate Production bindings - expose public transport - process real creator uploads - create permanent canon
LANE-004
STAGING Rules
STAGING may test: - route rendering - binding visibility - fake replay writes - fake heartbeat writes - fake intake validation - transport simulation - failure routing - rollback behavior STAGING must preserve: - separate test keys - separate test prefixes - no real creator uploads - no public transport - no canon mutation
LANE-005
PRODUCTION Rules
PRODUCTION may only receive: - verified pages - approved releases - known-safe route changes - persistent Pages Functions bindings - intentional public media - governed operational writes PRODUCTION must reject: - experiments - uncontrolled auto-write - unverified uploads - live transport tests - random cache injection - unscoped AI repair
LANE-006
R2 Experiment Rule
Production R2 buckets are not testing buckets. Experimental writes must use: - local fake data - DEV-only mock files - STAGING-only test prefixes - explicit test object keys Forbidden: writing fake events into live canon lanes without test prefix.
LANE-007
Test Prefix Rule
Any non-production test object must use an obvious prefix: test/ dev/ staging/ simulation/ mock/ failure-test/ No hidden test object may appear in canon paths.
LANE-008
Transport Experiment Rule
Magic Cursor transport experiments must begin as simulation. Allowed: - fake cursor move - fake heartbeat - fake replay registration - fake handoff - fake clipboard event - fake drag event Forbidden: - uncontrolled live pointer control - invisible clipboard transfer - drag transfer to public lane - device takeover - transport without replay
LANE-009
Creator Upload Experiment Rule
Creator upload testing must not begin in PRODUCTION. Upload testing sequence: 1. DEV fake upload 2. STAGING fake upload 3. STAGING validation 4. STAGING sequester route 5. STAGING deadletter route 6. Production release gate 7. limited live upload No public creator intake before validation chain exists.
LANE-010
Binding Mutation Rule
Production binding changes require: - one TASK only - full active binding restatement - Pages Functions path - no Workers settings API - no broad auto-write authority - report-only verification - freeze after success Production binding mutation is not experimentation.
LANE-011
Rollback-Safe Testing
Every test must answer: Can this be stopped? Can this be reversed? Can this be replayed? Can this be isolated? Can this be explained? If no: the test is not safe.
LANE-012
Final Rule
CyberCrowd grows by controlled experimentation, not production gambling. DEV can be messy. STAGING must prove. PRODUCTION must survive.
