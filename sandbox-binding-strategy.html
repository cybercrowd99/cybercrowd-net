CYBERCROWD SANDBOX BINDING STRATEGY V1
Binding strategy for CyberCrowd artificial operational sandboxes. This document defines how DEV and STAGING sandbox buckets connect without contaminating Production Pages Functions bindings.
BINDING-001
Core Rule
Sandbox bindings must never replace, erase, or mutate Production bindings. Production remains the protected continuity surface. Sandbox bindings exist for testing only.
BINDING-002
Production Binding Preservation
Current Production binding lattice must remain preserved: ARCHIVE DEADLETTER GOVERNANCE GRAPHICS LEDGER_EVENTS LINEAGE NODE_HEARTBEATS REPLAY SEQUESTER SURFACE_CACHE TEASERS Any Production binding mutation must restate the full active set. Sandbox work must not remove or replace this lattice.

BINDING-005
Environment Attachment Rule
DEV sandbox bindings attach only to DEV/local testing surfaces. STAGING sandbox bindings attach only to Preview/STAGING environments. Production bindings remain Production-only. No sandbox binding may be added to Production unless explicitly approved as a controlled test prefix path, and even then it must remain non-authoritative.
BINDING-006
Preview Environment Strategy
Recommended approach: Production: live operational lattice only Preview: STAGING bindings only Local DEV: DEV bindings only This prevents: - fake replay contamination - fake heartbeat pollution - sandbox intake reaching live lineage - simulated failures entering live deadletter
BINDING-007
No Crossover Rule
Forbidden: DEV_REPLAY bound to Production Forbidden: STAGING_REPLAY bound to Production canon Forbidden: DEV_HEARTBEATS bound to NODE_HEARTBEATS Forbidden: STAGING_SEQUESTER replacing SEQUESTER Forbidden: sandbox deadletter replacing Production DEADLETTER Forbidden: sandbox binding names matching Production names
BINDING-008
Promotion-Safe Binding Discipline
Promotion from sandbox to Production never means moving sandbox bindings. Promotion means: - prove behavior in DEV - prove behavior in STAGING - review results - implement clean Production route - preserve Production binding names - verify Production lattice Sandbox bindings are training wheels. Production bindings are operational rails.
BINDING-009
Cloudflare Binding Discipline
All binding work follows: <[team build]> TASK: one directive only DO NOT: containment boundaries ONLY: allowed binding action REPORT ONLY: verification output Never authorize broad auto-write. Never assume merge-state behavior. Never bind sandbox systems into Production accidentally.
BINDING-010
Verification Requirement
After each sandbox binding: 1. inspect target environment bindings 2. verify Production binding count unchanged 3. verify Production binding names unchanged 4. verify sandbox binding exists only where intended 5. verify no public exposure 6. freeze 7. continue Verification before expansion.
BINDING-011
Final Rule
Sandbox bindings exist to let CyberCrowd learn safely. Production bindings exist to let CyberCrowd survive. Do not confuse the two.
