CYBERCROWD LIVE INTAKE AUTHORITY FLOW V1
Live intake authority flow for CyberCrowd. This defines how objects enter the system before they become trusted, canonical, archived, cached, replayable, or publicly visible.
INTAKE-001
Core Rule
Nothing enters CyberCrowd as trusted. Every live object begins as intake. Every intake object must pass through: SEQUESTER before it can reach: LEDGER_EVENTS LINEAGE ARCHIVE REPLAY SURFACE_CACHE GRAPHICS TEASERS Rule: intake first trust later public last
INTAKE-002
Primary Intake Route
Object Type First Destination Validation Requirement Next Eligible Route
creator upload SEQUESTER identity, file type, ownership, safety LINEAGE, ARCHIVE, SURFACE_CACHE
public form payload SEQUESTER schema, spam, abuse, source check LEDGER_EVENTS or DEADLETTER
device mesh payload SEQUESTER session, device trust, replay ID REPLAY, NODE_HEARTBEATS, LEDGER_EVENTS
media preview SEQUESTER content type, size, release eligibility TEASERS or SURFACE_CACHE
graphics asset SEQUESTER format, size, naming, route eligibility GRAPHICS or SURFACE_CACHE
failed validation DEADLETTER failure reason recorded manual review only
INTAKE-003
Sequester Role
SEQUESTER is the first live holding lane. Purpose: - raw intake isolation - suspicious payload containment - untrusted upload holding - pre-public validation - pre-archive validation - pre-ledger eligibility check SEQUESTER is not: - public storage - archive storage - cache storage - final creator inventory - settlement truth Status: private controlled reviewable temporary until classified
INTAKE-004
Deadletter Role
DEADLETTER receives failed intake. A payload routes to DEADLETTER when: - schema fails - ownership cannot be proven - replay ID conflicts - payload is malformed - route is forbidden - security flags trigger - file is oversized for lane - public release condition fails DEADLETTER does not retry automatically. Manual review is required before re-entry.
INTAKE-005
Authority Assignment
After validation, each object receives an authority class: CANON → LEDGER_EVENTS OWNERSHIP → LINEAGE PRESERVATION → ARCHIVE REPLAYABLE → REPLAY PUBLIC_DELIVERY → SURFACE_CACHE, GRAPHICS, TEASERS TELEMETRY → NODE_HEARTBEATS FAILED → DEADLETTER QUARANTINED → SEQUESTER
INTAKE-006
Release Conditions
An object may become public only when: - identity source is known - ownership status is assigned - file type is allowed - route target is correct - no security flag is active - no governance hold exists - lineage eligibility is recorded - cache eligibility is confirmed - public exposure is intentional Public release without these conditions is forbidden.
INTAKE-007
Forbidden Shortcuts
Forbidden: public upload → ARCHIVE Forbidden: public upload → SURFACE_CACHE without validation Forbidden: creator object → LINEAGE without ownership check Forbidden: device event → LEDGER_EVENTS without session authority Forbidden: failed payload → public lane Forbidden: cache object → canonical truth Forbidden: governance override → silent mutation
INTAKE-008
Replay Registration
Replay registration occurs only after: - event ID exists - source is known - replay ID is unique - origin lane is recorded - target lane is recorded - failure route is known Replay is not canon. Replay reconstructs canon.
INTAKE-009
Live Intake Sequence
1. object arrives 2. object enters SEQUESTER 3. object receives temporary intake ID 4. validation runs 5. route authority is assigned 6. failure routes to DEADLETTER 7. valid object receives lineage or ledger record 8. archive eligibility is decided 9. cache eligibility is decided 10. public release occurs only after authority clears
INTAKE-010
Final Rule
CyberCrowd does not trust arrival. CyberCrowd trusts lineage, validation, authority, and replayable records. Build empty boxes first. Verify connections second. Live transport last.
