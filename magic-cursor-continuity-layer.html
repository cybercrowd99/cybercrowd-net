CYBERCROWD MAGIC CURSOR CONTINUITY LAYER V1
Cross-device continuity layer for Magic Cursor. This document defines how cursor authority, device handoff, session migration, replay continuity, and heartbeat continuity survive across multiple surfaces.
CURSOR-001
Core Rule
Magic Cursor is not a loose pointer. Magic Cursor is a controlled continuity rail. Every cursor action must belong to: - one session - one device owner - one authority scope - one replay chain - one heartbeat chain - one active surface No orphan cursor authority. No silent device takeover. No untracked handoff.
CURSOR-002
Continuity Identity
Every Magic Cursor session receives: cursor_session_id device_origin_id device_target_id continuity_id replay_id heartbeat_id authority_scope handoff_state Purpose: preserve cursor history across device movement.
CURSOR-003
Cursor Ownership
Ownership State Description Allowed Action Failure Route
unclaimed No active cursor authority. request session SEQUESTER
claimed One device owns cursor control. move, click, route REPLAY
handoff_pending Cursor is moving between devices. freeze until confirmed DEADLETTER
handoff_confirmed Target device accepts authority. resume cursor control REPLAY
revoked Authority removed. none GOVERNANCE
CURSOR-004
Device Handoff Route
Handoff sequence: 1. origin device requests handoff 2. session authority validates request 3. heartbeat confirms origin device alive 4. target device confirms readiness 5. replay records pre-handoff state 6. cursor authority freezes 7. target device claims cursor 8. replay records post-handoff state 9. heartbeat continuity continues If any step fails: route event to DEADLETTER or SEQUESTER.
CURSOR-005
Session Migration
Session migration occurs when: - phone becomes controller - laptop becomes controller - tablet joins surface - observer station takes role - creator station resumes control - VR node becomes active Migration must preserve: - session identity - replay continuity - lineage reference - authority scope - heartbeat chain - last known cursor state
CURSOR-006
Heartbeat Continuity
NODE_HEARTBEATS records: - active device - standby device - latency - last cursor state - handoff timing - session liveness - drop detection Heartbeat loss may: - freeze cursor authority - trigger replay reconstruction - route failure to DEADLETTER - request governance review
CURSOR-007
Replay Reconstruction
REPLAY records: - cursor position - active device - target surface - click state - drag state - clipboard state - handoff state - failure state Replay can reconstruct cursor state after: - dropped connection - device sleep - refresh - accidental disconnect - session timeout
CURSOR-008
Authority Preservation
Cursor handoff cannot change authority class. A viewer does not become creator. A device does not become owner. A session does not become governance. A replay does not become canon. Authority follows verified identity, not hardware possession.
CURSOR-009
Clipboard + Drag Continuity
Clipboard and drag transfer require: - active session - allowed device pair - replay registration - source surface - target surface - payload classification - sequester fallback Forbidden: clipboard payload bypassing SEQUESTER when suspicious drag payload reaching public lane without validation device-originated file entering ARCHIVE directly
CURSOR-010
Interruption Recovery
If continuity breaks: 1. freeze cursor action 2. preserve last replay state 3. preserve heartbeat loss event 4. mark session degraded 5. route failure to DEADLETTER 6. attempt safe reconstruction 7. require re-confirmation before control resumes No blind resume. No silent takeover.

CURSOR-012
Final Rule
Magic Cursor must feel seamless to the user, but it must never be invisible to the system. Seamless surface. Traceable interior. Every motion, handoff, pause, failure, and recovery must have a replayable authority path.
