DEPLOYMENT LANE MAP
Failure containment, lane separation, and operational survival pattern.
Small target fails. Whole environment survives.
One deployment lane must never collapse every subsystem simultaneously.
Pages Lane

LIVE

Current public Cybercrowd site deployment lane.

  • GitHub source
  • Cloudflare Pages deployment
  • Static public HTML surfaces
  • Live operational visibility

Effect pattern: if Pages is healthy, the public site remains visible.

Worker Lane

PARKED

Future runtime and API execution lane.

  • Wrangler deploys
  • Worker runtime logic
  • Future API routing
  • Future edge execution

Effect pattern: Worker failure must not stop the Pages site.

R2 Lane

PARKED

Future media, storage, sales, graphics, and teaser bucket lane.

  • ALBUM bucket parked
  • GRAPHICS bucket preserved
  • TEASERS bucket preserved
  • Future media architecture retained

Effect pattern: one bucket validation failure must not collapse deployment.

Functions Lane

PARKED

Future server-side Pages Functions lane.

  • Server logic
  • Form handlers
  • Auth helpers
  • Future integrations

Effect pattern: Functions return only when intentionally activated.

Operations Lane

LIVE

Operational visibility and coordination surfaces.

  • Operations Dashboard
  • Operations Map
  • Continuity Dashboard
  • Retention and broadcast panels

Effect pattern: operations visibility continues while other lanes are isolated.

Future Media Lane

FUTURE

Separated media commerce and creator asset architecture.

  • Album sales media
  • Graphics delivery
  • Teaser publishing
  • Creator asset routing

Effect pattern: media returns as its own lane, not as a hidden dependency.

Deployment topology matters as much as code topology.
Pages, Workers, R2, Functions, Operations, and future media systems must remain separated enough that one failure cannot burn the whole house.
Current lock: GitHub → Cloudflare Pages → live site.
Parked lock: Workers, Wrangler, R2 bindings, and Functions return only through intentional lane activation.
